# PRD-20217 · autotask_create_contact：未传 isActive 时默认 1

## 背景

本单原始问题（`POST /Contacts` 返回 IIS 404）已由 Leo Yang 在 `8661536` 修复，并于 2026-10-12 随 `9700dde` 发布到 PRD。
QA（Pantene Hui）在 2026-10-15 的跟进 comment 中报告了新问题：调用已能到达 Autotask，但首次调用经常失败：

> Autotask POST /Companies/29683561/Contacts failed: HTTP 500: Missing Required Field: isActive.

证据（sopId 974，prod，2026-10-14）：T20261014.0023 / .0027 / .0029 首次失败、重试成功；T20261014.0033 首次失败且未重试，联系人未创建。
skill 层已要求 agent 传 `isActive=1`，模型仍多数漏传，无法靠 prompt 可靠解决。

## 需求来源说明

本单**没有设计棒产出的产品设计 / 技术设计 / 用例**。验收标准直接取自 QA 2026-10-15 的 comment，**由 dev 拟定用例、未经 groom 确认**，接手者请多看一眼。

QA 给出的验收标准：

1. 调用 `autotask_create_contact(companyID, firstName, lastName)` 且不传 `isActive`，创建出启用状态的联系人，不出现 HTTP 500。
2. 重跑一张入职工单，首次调用即出现 `Created Autotask contact <name>`。（需 PRD 环境，见「未执行」）

## 根因（代码证据，基线 9700dde）

- `src/handlers/tool.definitions.ts:345` `autotask_create_contact` 的 `inputSchema` 只列了 companyID / firstName / lastName / emailAddress / phone / title，**没有 `isActive`**，模型看不到这个字段。
- `src/handlers/tool.handler.ts:892` 把入参原样交给 `createContact`。
- `src/services/autotask.service.ts:366` `createContact` 原样转发给 `POST /Contacts` 及 404 回退的 `POST /Companies/{id}/Contacts`，**不补任何默认值**。
- Autotask Contacts 实体要求 `isActive`（`src/types/autotask.ts:31` 注释：数字类型，非布尔）。

## 改动

| 文件 | 改动 |
| `src/services/autotask.service.ts` | `createContact` 在两条请求路径之前统一构造请求体：`isActive: input.isActive ?? 1`。显式传 0 保留；不修改调用方对象 |
| `src/handlers/tool.definitions.ts` | `autotask_create_contact` 入参新增 `isActive`（number，`default: 1`，说明「不传默认 1」）。不加入 `required`，因为服务端已兜底 |
| `tests/contact-create-isactive.test.ts` | 新增 6 条用例，断言实际发出的请求体 |

选择与理由：默认值放在服务层（唯一的请求出口），而不是 handler，这样直连 POST 与 404 回退两条路径共用同一请求体；不把 `isActive` 设为 required，避免对旧调用方增加约束（仓库无 schema 校验层，见 CLAUDE.md 第 20 行）。
